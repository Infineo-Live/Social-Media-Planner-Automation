**Project:** Infineo - Social Media Planner  
**Document Version:** 1.0  
**Status:** Draft

---

# 1. Purpose

This document defines all email notifications generated by the application.

Emails exist only to notify users when they are expected to take an action or when an important workflow event has occurred.

The objective is to ensure that users are informed without creating unnecessary email traffic.

---

# 2. Email Principles

The application shall follow these principles for all outgoing emails.

- Every email must have a single purpose.
- Emails must be short and actionable.
- Emails must contain a direct link to the Content Item.
- Emails must never include sensitive information.
- Emails must be automatically generated by the system.
- Duplicate emails for the same event must not be sent.
- Emails must always include the Content Item ID and Working Title.

# 5. Email Variables

The following placeholders are available for email generation.

| Variable | Description |
|----------|-------------|
| {{RecipientName}} | Recipient's name |
| {{ContentID}} | Internal Content Item ID |
| {{WorkingTitle}} | Working title of the reel |
| {{Series}} | Series name |
| {{SubSeries}} | Sub-Series name (if applicable) |
| {{Status}} | Current workflow status |
| {{AssignedBy}} | User assigning the task |
| {{AssignedTo}} | Assigned employee |
| {{PreviousStatus}} | Previous workflow status |
| {{NewStatus}} | New workflow status |
| {{ApplicationLink}} | Direct link to the Content Item |

# 21. Email Frequency Rules

The application shall send emails immediately after the triggering event.

Emails are never batched.

The application shall not send reminder emails.

The application shall not send daily summaries.

The application shall not send weekly summaries.

---

# 22. Duplicate Prevention

The application shall prevent duplicate emails for the same workflow event.

A single workflow action shall generate only one email per recipient.

---

# 23. Failed Email Delivery

If an email cannot be delivered:

- The workflow shall continue normally.
- The failure shall be recorded in the system log.
- The application shall not block user actions.
- The application shall not repeatedly retry sending emails automatically.

---

# 24. Future Expansion

Future versions may support:

- Daily digest emails
- Weekly summaries
- Email preferences per user
- CC recipients
- Rich HTML email templates
- Calendar invitation emails
- Slack or Microsoft Teams notifications

These features are outside the scope of Version 1.
